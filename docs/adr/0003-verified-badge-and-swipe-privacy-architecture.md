# Two-Sided Verified Badge System & Swipe Privacy Architecture

To establish high bilateral trust in a student housing marketplace without human verification teams in MVP, we decided on a dual-tier badge verification model: Students achieve a Verified Badge via institutional `.edu` email authentication or student ID photo attachment, while Landlords achieve a Verified Badge via property document/permit upload (or admin demo toggle). To protect student browsing privacy, student swipes (left and right) are stored in private actor subcollections (`users/{uid}/swipes/{targetId}`) rather than a single public collection. When a student likes a listing, a lightweight referral pointer is placed in `listings/{listingId}/likes/{studentUid}` exposing only verified badges and public tenant preference tags to the landlord's Review Queue.
